**走查对象**：运行中的 Tauri 桌面客户端 v0.8.1（`src-tauri/target/release/ai-ssh-pro.exe`）
**走查方式**：WebView2 CDP（后台截图 + DOM/计算样式读取），全程未抢占窗口焦点，未连接任何真实生产主机

## 0. 结论摘要

主界面的整体信息架构是**成熟且自洽的**：左侧会话树 — 中间工作区 — 右侧 AI 面板的三栏结构清晰，告警工作台、运维首页、设置页的信息密度和视觉层级都达到了可用水准；主题切换、命令面板、toast 反馈完善。

真正需要处理的**高优先级问题集中在窄窗口（1024px）**：三栏布局没有降级策略，中间工作区被压到 173px，导致运维首页内容逐字竖排、完全不可读。其次是新建连接面板的 Escape 关闭失效、底部操作栏遮挡表单内容等交互细节问题。

## 1. 详细发现

### UX-W01 · P1 · 1024px 窄窗口三栏布局崩溃

**证据**：`61-narrow-1024.png`；DOM 实测（`node tools/cdp-a11y-narrow.mjs`）

```
viewport 1024, docScrollW 1024
.main               scrollW 426  clientW 173
.terminal-stack     scrollW 426  clientW 173
.oh-scroll          scrollW 299  clientW 163
.oh-tasks           scrollW 274  clientW 113
.oh-rows            scrollW 264  clientW 113
.oh-section         scrollW 240  clientW 115
verticalText: "全部" w=30 h=55
```

**现象**：
- 窗口宽 1024 时，左会话栏仍占约 370px，右 AI 面板占约 450px，中间工作区仅剩 **173px**。
- 运维首页的"运维首页"标题被拆成"运维 / 首页"两行；"进行中 / 全部 / 已忽略"筛选按钮被压成竖排单字（"全部"实测 30×55px）；"0 台在线 / 1 条待处理 / 更新于 刚刚"逐字换行。
- 主机卡片区域出现横向滚动条（`.oh-scroll` 299 > 163），内容无法完整查看。
- 顶部标签栏同样溢出（`.tab-bar` 188 > 173）。

**影响**：1024×768 是常见的笔记本/分屏分辨率，此宽度下**中间工作区（最核心的终端/运维区）不可用**。用户只能手动收起侧栏或 AI 面板才能恢复，但应用没有引导或自动降级。

**建议**（按投入从低到高）：
1. **响应式断点**：`max-width: 1180px` 时自动折叠左侧会话栏为图标条（保留 UX 已有的 `Ctrl+Alt+1` 手动折叠能力），把宽度让给中间区；`max-width: 1024px` 时进一步把 AI 面板改为可呼出的抽屉（`Ctrl+Shift+A` 已存在）。
2. **中间区最小宽度保护**：给 `.main` 设 `min-width: 420px`，三栏容器在不足时优先挤压 AI 面板而非中间区。
3. **运维首页自身降级**：`oh-*` 组件在容器 < 320px 时改为单列紧凑布局，筛选按钮组改横向 `overflow-x:auto` + 隐藏滚动条（参考 UX-55 标签条做法），标题 `white-space:nowrap`。
4. 首次进入窄窗口时给一次性 toast 提示"按 Ctrl+Alt+1 收起会话栏获得更多空间"。

### UX-W02 · P2 · 新建连接面板 Escape 无法关闭

**证据**：`26-new-connection.png`（Escape 后仍存在）、`30-main-light.png`（多次 Escape 后"新建连接 ×"标签仍在标签栏）

**现象**：通过顶部"+ 新建连接"打开面板后，按 `Escape` 无反应；面板以标签形式常驻标签栏，只能点标签上的 `×` 关闭。

**影响**：与命令面板、菜单、QuickPick（这些 Esc 都能关）的交互约定不一致，用户会形成错误预期。命令面板底部还明确写着"Esc 关闭"，反差更明显。

**建议**：为新建连接标签/面板补 `Escape` 关闭逻辑（焦点在输入框时先失焦、在下拉/日期浮层时先关浮层，再按一次才关面板）。全局 `keydown` 处理里注意与命令面板 `cmdp-backdrop` 的层级互斥，避免 Esc 一次关掉多个浮层。

---

### UX-W03 · P2 · 新建连接页底部固定按钮栏遮挡表单内容

**证据**：`26-new-connection.png`
**现象**：中间面板底部固定的「取消 / 保存到列表 / 保存并连接」按钮栏压住了"保护级别"单选组——"普通 / 生产 / 只读"三个 radio 只露出上半部分，标签文字被裁切。用户需要滚动才能完整看到，但滚动区没有明显提示。

**建议**：给可滚动内容区增加 `padding-bottom`（≥ 按钮栏高度 + 12px），或把按钮栏改为非固定（随内容滚动到底部）。保护级别是安全相关设置，不应被遮挡。

---

### UX-W04 · P3 · 窄窗口工具栏文字标签丢失且无补偿

**证据**：`61-narrow-1024.png`
**现象**：1280 宽下顶部工具栏显示"监控 / 工具箱 / SFTP"文字，1024 宽下全部收缩为图标。图标本身无 `title` 提示（DOM 检查发现 SFTP 按钮 `title="先连接一台主机"`，是状态提示而非功能名），首次使用或低辨识度图标下用户难以识别。

**建议**：给图标按钮统一补 `aria-label` + `title`（功能名 + 快捷键），如 `监控 (Ctrl+Shift+M)`；窄窗口下 hover 显示 tooltip。

---

### UX-W05 · P3 · AI 面板引导 toast 与输入框重叠（待确认）

**证据**：`21-cmdk.png`、`30-main-light.png` 右下角
**现象**：AI 面板底部出现"接下来…传…"的引导条/浮层，与输入框区域部分重叠；`41-terminal-output.png` 中该浮层已消失，说明是阶段性新手引导。

**建议**：确认该引导是否为首次启动引导；若是，应：
- 定位在输入框**上方**而非覆盖输入区；
- 提供明确的"知道了 / 不再显示"关闭入口（截图中似乎有"不再显示"按钮，但被截断）；
- 多步引导应有进度指示（如 1/3）。

---

### UX-W06 · P3 · 告警工作台未连接主机的"定位"反馈偏被动

**证据**：`20-cdp-main.png`
**现象**：告警列表选中 `172.19.161.121 disk 90%`，详情区显示黄褐色提示条"该主机当前未连接，无法实时排查"，但下方"定位"按钮仍为高亮可点状态；点击后的预期行为不明确（跳到会话树？发起连接？）。

**建议**：把"定位"按钮改为明确的动作语义——若未连接则显示"连接并定位"或直接弹出连接确认；并在 tooltip 中说明会做什么。

## 2. 做得好的地方（保持）

- **三栏结构与职责划分**：会话树 / 工作区 / AI 面板边界清晰，宽度可调（拖拽分隔条存在）。
- **命令面板**：Ctrl+K 唤起，分组（连接类）、快捷键提示、底部操作说明齐全；主输入框 placeholder "搜索功能，如 监控、转发、备份…" 给出了可用范围示例。
- **主题系统**：UI 主题（含浅色/沙色/海洋/森林）与终端主题联动（实测切换后终端前景色从 `rgb(230,237,243)` 正确变为 `rgb(31,35,40)`，github-light 主题，白底对比度约 14:1）。
- **主题切换 toast**：右下角"已切换到浅色主题 / 已切换到深色主题"反馈及时。
- **标签栏溢出处理**：`tab-bar-scroll` 带 `fade-left fade-right` 渐隐（UX-55 既定方案），1280 宽下无全局横向溢出（`docScrollW = 1280`）。
- **可访问性基础**：DOM 检查中所有可见按钮均有 `aria-label` / `title` / 文本内容，无无名按钮。
- **运维首页**：主机卡片的 CPU / 内存 / 磁盘进度条 + 生产标签 + 终端/SFTP/监控快捷入口，信息密度和视觉层级合理。
- **快捷键盘约定统一**：Ctrl+K 命令面板、Ctrl+Alt+D 主题切换、Ctrl+Alt+1 会话栏、Ctrl+Shift+A AI 面板，菜单中都有标注。
- **未连接状态的禁用处理**：SFTP 按钮在未连接时 `is-dim` 且 `title="先连接一台主机"`，状态反馈清晰。

## 3. 走查覆盖范围与局限

**已覆盖**：主界面（深/浅）、命令面板、文件/查看/帮助/运维菜单、新建连接、设置（通用）、本机终端、资源监控主机选择器、运维首页、1024 窄窗口响应式。

**未覆盖**（需要真实 SSH 连接或特定数据状态）：SFTP 文件树与传输队列、服务器工具箱（进程/服务/端口/日志）、AI 执行计划与确认流程、批量执行、告警规则编辑、云同步/备份等。这些入口在未连接状态下为禁用，本次未连接任何真实主机以避免影响你的环境。

**方法局限**：走查基于 CDP 截图与 DOM 计算样式，对比度和溢出为客观测量；交互类问题（如 Escape 失效）基于自动化按键后的界面状态推断，建议开发侧复核。

## 4. 建议的修复顺序

1. **先做 UX-W01**（P1，1024 响应式）——影响面最大，建议作为独立批次。
2. **再做 UX-W02 + UX-W03**（P2，新建连接）——同一个面板，可一起修。
3. **最后 UX-W04 / W05 / W06**（P3）——穿插到后续细节打磨批次。

> 本次走查**未修改任何应用代码**。为走查新建的临时脚本位于 `tools/`（capture-window*.py、cdp-*.mjs），截图证据位于 `e2e-artifacts/ux-walkthrough/`，可按需要清理或保留。
